# NTE 比赛 × AstrBot 插件

把「NTE 比赛」平台的赛事数据接进 QQ 群：**19 条群命令，全部由 AstrBot 的命令过滤触发**。

* **不依赖任何大模型**：插件不注册 `llm_tool`、也不发任何 LLM 请求——同一个问题问两次，
  回答一样；关掉大模型 / 不配 provider 完全不影响使用；
* **问帮助可以直接回图**：配好 `help_image`，`比赛帮助` 就发那张图（见「帮助文档与帮助图」），
  方便贴群公告、也方便群友转发。

插件本身不做业务计算，只调站点的只读查询 API（`/api/bot/*`），所以文案 / 赛制 /
分页逻辑只有站点那一份，改一处两边同步。

站点源码（含本插件）：<https://github.com/PureAmaya/NTEmatch> · AGPL-3.0 · © 早八时睡觉的你

## 安装

1. 把本目录（`astrbot_plugin_nte_match`）整个复制到 AstrBot 的 `data/plugins/` 下：

  ```bash
  # 假设 AstrBot 的数据目录是 /opt/astrbot/data
  cp -r astrbot_plugin_nte_match /opt/astrbot/data/plugins/
  # Docker 部署：拷进容器（拷完在面板「插件管理」里重载，或重启 AstrBot）
  docker cp astrbot_plugin_nte_match <容器名>:/AstrBot/data/plugins/
  ```

> **别在 AstrBot 面板里用「从 URL 安装」填本站的插件地址**——它会 404，且与网络无关：
> 面板认的是 GitHub 的 `…/tree/<分支>/<子目录>`，而下载时走的是 codeload 的
> `…/zip/refs/heads/<分支>`，**codeload 只给整仓 zip、不接受子目录**，于是
> `…/NTEmatch/zip/refs/heads/master`（整仓）是 200，
> `…/master/integrations/astrbot_plugin_nte_match` 是 404。这条路要求
> **仓库根目录就是插件**，而本插件在整站的子目录里，所以只能「拷目录」这一种装法。


2. 到 **NTE 比赛站点 →「服务器 → QQ 机器人 → 查询接口令牌」**点「生成令牌」，
   复制那串 `nte_…`（**只显示一次**）；
3. 在 AstrBot 的 **插件管理 → NTE 比赛 → 配置**里填：

   | 配置 | 说明 |
   | --- | --- |
   | `base_url` | 站点地址，如 `https://match.example.com`（不带尾部斜杠） |
   | `api_token` | 上一步生成的 `nte_…` |
   | `timeout` | 请求超时（秒），默认 10 |
   | `reply_prefix` | 回复前缀（可留空） |
  | `help_image` | 「比赛帮助」要发的**帮助图**；**留空（默认）= 用站点内置那张 `/help.jpg`**（站点没放图则回私聊文字说明），填网址 / 本机路径可覆盖 |
   | `call_cooldown` | 「比赛召集」同一会话的最小间隔（秒），默认 60；0 = 不限 |
   | `call_per_hour` | 「比赛召集」每小时上限（同一会话），默认 6；0 = 不限 |

4. 重载插件。加载日志里会先出现一行 `[NTE 比赛] 已连接站点 | …`（自检通过）；
   然后**在群里 @ 机器人**发「比赛帮助」试试（注意要 @，见下面「怎么触发」）。

## 命令

**全部能力都是命令**：下面这些问法都由命令直接回答，**不经过任何大模型**——所以答案稳定、
可复现，也不花 LLM 请求。命令覆盖不到的自由问法会**没有回应**（群里会沉默），
这也是下面别名收得比较宽的原因。

| 命令 | 说明 | 别名 |
| --- | --- | --- |
| `比赛` | 当前赛事的信息 + 进度 | `当前比赛`、`赛事`、`ntematch` |
| `比赛直播` | **当前谁在直播**（主直播间 + 选手 / 成员机位与观看地址） | `直播`、`当前直播`、`谁在播`、`谁在直播`、`直播间`、`开播了吗`、`ntelive` |
| `比赛列表 [页码]` | 全部赛事（分页） | `全部比赛`、`历届`、`往届`、`比赛目录`、`nte列表`、`有哪些比赛` |
| `比赛届次` | 全部届次的编号与名称（填参数用） | `届次列表`、`比赛编号` |
| `比赛信息 [届次]` | 时间 / 赛制 / 人数 / 简介 / 是否排名 | `赛事信息`、`比赛时间` |
| `比赛进度 [届次]` | 已赛多少、正在打谁 vs 谁 | `进度`、`赛程`、`赛程进度`、`现在打谁`、`nte进度`、`打到哪了`、`谁领先`、`什么情况` |
| `比赛下一场 [届次]` | 接下来看哪场（含计划时间） | `下一场`、`下场`、`接下来`、`现在打`、`接着打谁`、`等下打谁` |
| `比赛结果 [届次]` | 冠军 / 榜单 + 逐场比分 | `结果`、`成绩`、`比分`、`nte结果`、`赢了吗`、`什么比分`、`结果咋样` |
| `比赛冠军 [届次]` | 冠军（或积分制榜首前三） | `冠军`、`榜首`、`谁赢了` |
| `比赛名单 [届次]` | 参赛名单（选手 / 队伍 / 替补） | `参赛名单`、`选手名单`、`比赛选手`、`队伍`、`都有谁` |
| `比赛详情 [届次] [场次]` | 综合信息；给场次编号细说那一场 | `赛事详情`、`场次详情`、`单场` |
| `比赛召集 [届次]` | **@ 本届参赛者**，请他们到场准备（**限举办者 / 服务器管理员**，带冷却） | `召集参赛`、`集合`、`喊人` |
| `比赛我的` | **私聊**发你**自己的推流地址 + 站点里的直播间地址**（按发命令的 QQ 认人） | `我的推流`、`我的直播间`、`推流地址`、`我的地址` |
| `比赛重置密钥 [@某人]` | 换登录密钥（新密钥**私聊**发给被改的人，旧密钥立即失效）；`@某人` 仅服务器管理员 | `重置登录密钥`、`我的密钥`、`换密钥` |
| `比赛重置令牌 [@某人]` | 换直播令牌（Bearer；要求先有推流码，新令牌**私聊**发给被改的人） | `重置直播令牌`、`我的令牌`、`换令牌` |
| `比赛改推流码 <流名> [@某人]` | 改推流码（推流 ID；令牌不变，OBS 里的地址要跟着换） | `修改推流码`、`设置推流码`、`我的推流码` |
| `比赛授权 @某人` | 把群友设为**赛事管理员**（**限服务器管理员**；还不是成员就自动建号，密钥私聊给本人） | `授权赛事管理员`、`授予赛事管理员`、`设为赛事管理员` |
| `比赛添加 @某人` | 把群友添加为**普通成员**（**限服务器管理员**） | `添加成员`、`添加群友`、`比赛添加成员`、`设为成员` |
| `比赛帮助` | 帮助：配了 `help_image` 就**当场发图**，否则把命令列表**私聊**发给提问者 | `赛事帮助`、`比赛命令`、`比赛功能`、`ntehelp`、`比赛help` |

**关于「私聊发你」**：这几条由站点代发私聊（插件把内容交给站点，站点用它的 AstrBot 通道发）。
（例外：`比赛帮助` 配了帮助图时改为**当场发图**，不经过站点。）
私聊发不出去时（没加机器人好友）会退回群里回；但**登录密钥除外**——密钥只显示一次，
泄在群里等于白送一个账号，所以密钥发不出去就只回复一句「请找管理员重置」。

### 群里授权 / 添加成员（先做这一步配置）

`比赛授权 @某人` / `比赛添加 @某人` 会把人拉进站点。**两个前提**：

1. **操作者（服务器管理员）要先在站点「我的」页填上自己的 QQ**——认人只认 QQ，
   对不上就一律拒绝（这是刻意的：令牌只代表「这是本站的机器人」，不代表权限）；
2. 机器人推送要在站点「服务器 → QQ 机器人」里**已启用**（密钥与地址都配好），
   否则私聊发不出去。

几条硬规矩（都在站点那侧执行，插件绕不过去）：

| 规矩 | 为什么 |
| --- | --- |
| 只有**服务器管理员**能授权 / 添加 | 否则群里任何人对机器人说一句话就能给自己发权限 |
| 权限只能是**普通成员 / 赛事管理员** | 不许经群命令授予 server_admin（全站只有一位，最高权限，请到站点改） |
| 已是成员 → **只改权限，不碰密钥** | 换权限不该顺手把人家的登录口令作废 |
| 新建成员 → 密钥**私聊**给本人、只出现一次 | 群里发密钥等于白送账号 |
| 必须真的 @ 到人（不认手打 QQ） | 抄错一位就等于给陌生人开了权限 |

### 成员自助：换密钥 / 换令牌 / 改推流码

不 @ 人 = **改自己**（谁都能改自己的，不需要服务器管理员）；`@某人` = **替 TA 改**，
这需要**服务器管理员**：

| 命令 | 做什么 | 结果 |
| --- | --- | --- |
| `比赛重置密钥 [@某人]` | 换一把登录密钥（旧密钥立即失效） | **私聊**发给**被改的那个人** |
| `比赛重置令牌 [@某人]` | 换一把直播令牌（Bearer；**要求先有推流码**） | **私聊**发给**被改的那个人**（含推流地址） |
| `比赛改推流码 <流名> [@某人]` | 改推流码（推流 ID；令牌不变） | **私聊**发给**被改的那个人**（含新地址） |

* **新值只发给被改的人**：代改时服务器管理员也看不到（他要的只是「帮不上线的人重置」）；
  私聊里会写明「这次由服务器管理员「某某」帮你重置」，本人对不上号就能立刻再改一次；
* **新值不经插件**：站点把密钥 / 令牌直接私聊给本人，接口只回「发了没有」——
  所以插件这一侧**结构上**没有把凭据打进群的机会（不是靠自觉）；
* **私聊里会提醒**：任何拿到密钥 / 令牌的人都能用它登录 / 推流，觉得可能泄露就
  **立刻再发一次同样的命令**换一把（旧值随即作废）；
* **私聊发不出去时**：群里的回话会说清「**已经换好了**、只是你没收到」——先加机器人好友，
  再发一次同样的命令即可；否则本人会以为没生效而反复重试（每试一次作废一把）；
* **没有推流码就不发令牌**：令牌没有可填的地方，先发「比赛改推流码」设一个。

### 怎么触发（**先看这一节**）

命令**不是「群里打这几个字就出来」**——AstrBot 的命令过滤要求消息被 @ 或命中唤醒前缀
（源码 `CommandFilter.filter` 的第一行就是 `if not event.is_at_or_wake_command: return False`）。
所以正确写法是：

| 写法 | 是否触发 | 说明 |
| --- | --- | --- |
| `@机器人 比赛进度` | ✅ | 最稳，任何配置下都行 |
| `/比赛进度` | ✅ | 前提是 AstrBot 的**唤醒前缀**设了 `/`（默认通常有） |
| `比赛进度`（直接发） | ❌ | 未命中 @ 与前缀 → 命令不执行，机器人**完全沉默**（本插件不用大模型，不会有兜底回答） |

两条补充：

* **注意**：不 @ 也不带前缀时，命令不会执行、也没有任何兜底，群里会**完全沉默**。
  建议在群公告里写一句「请 @ 机器人 或用 `/` 开头」，并把**帮助图**一起贴在公告里。
* 命令匹配按**词边界**（`指令名 + 空格` 或完全相等），所以短命令不会吞掉长命令：
  「赛事信息」不会被「赛事」抢走；同时因为都带 `比赛` / `赛事` / `nte` 前缀，
  也不会和 AstrBot 的内置命令撞车。

### 不依赖大模型

命令是 AstrBot 的**命令过滤**（纯字符串匹配），在「要不要请求大模型」这一步**之前**就处理完了。
本插件更进一步：**它压根不注册 LLM 工具、也不发任何 LLM 请求**——

* 插件只对站点发只读 HTTP（`/api/bot/*`），回什么完全由站点数据决定；
* 站点往群里推的消息（`/api/qqbot/push`）同样不经过大模型；
* 所以**关掉大模型 / 不配 provider，一切照常**，也不会出现「同一句话每次答得不一样」。

代价只有一处：**自由问法没有兜底**（例如「我们下把打谁啊」→ 机器人沉默）。
所以别名特意收得比较宽——常见口语（`谁领先`、`打到哪了`、`赢了吗`、`谁在播`…）
都挂成了命令别名；**问帮助**还有一条更省事的捷径：配一张帮助图放在群公告里。

## 赛前提醒（站点发，不是插件）

开赛**前一天**与**前 2 小时**在群里 @ 举办者——这条由**站点**定时发（`app/remind.py`），
不经过插件：只有站点知道开赛时间，也只有它握着推送通道。开关与提前量在
「服务器 → QQ 机器人 → 赛前提醒」，默认开、提前量 `1440,120`（分钟）。

插件这边不用配任何东西；只要推送本身是通的（下面第 2 条），提醒就发得出去。

## 帮助文档与帮助图

命令说明有**两份**（同一内容、两种用途）：

| 位置 | 用途 |
| --- | --- |
| `main.py` 里的 `HELP_TEXT` | 群命令 `比赛帮助` 私聊回的那段文字（**运行时唯一的说明来源**） |
| `HELP.md` | **帮助图的生成 prompt**：整段复制给 AI 绘图工具即可出图（含站点配色与 19 条命令全文） |

> `HELP.md` 现在是**给 AI 的指令**，不是给人看的文档：里面写死了站点**真实的**配色
> （`#07090f` 底 / `#22e0e8` 主色 / `#ff2f8e` 副色）、卡片描边与圆角、字体气质，
> 以及要逐字渲染的 19 条命令——这样出图风格与站点一致，不会画成另一种风格的海报。
> 换主色（「服务器 → 界面配置」）之后顺手改一下 prompt 里的色值再重画即可。

**发帮助图只要一步：把图放成站点项目里的 `static/help.jpg`。**

* **默认就发这张图，插件不用配任何东西**：插件先去 `https://你的站点/help.jpg` 探一下——
  在，就当场发图；**没放图就老实回文字说明**，不会给群友发一张加载失败的破图；
* `.jpg` / `.jpeg` / `.webp` / `.svg` 也认（站点按这个顺序取第一个存在的）；换图后
  **地址不变**，什么都不用改（`/help.jpg` 路径短、不随资源版本号变，和分享图一个路子）；
* 想用**别处**的图（图床 / AstrBot 本机路径）：在插件配置里填 `help_image` 覆盖默认值——
  **填了就照发**，不再去探站点；
* 发图一律发在**当前会话**（谁问发哪）：图是给人看和转发的，所以不像文字那样走私聊；
* 图与 `HELP_TEXT` **不会自动同步**——命令改了，请顺手更新 `HELP.md` 并重做图，
  否则群里回的文字与图会对不上（`HELP.md` 开头也写明了这一点）。

> 用的都是 QQ 不认 Markdown 这件事的老经验：文字说明一律**纯文本**（`**` 会原样显示成星号），
> 而图里的排版随便你——这正是做图的意义。

**届次必须写明**（带上 `[届次]` 的命令），写法很宽松：

| 写法 | 结果 |
| --- | --- |
| `e001` | 按编号精确匹配 |
| `1` / `第2届` | 先按编号数字匹配，再按「第 N 届」算 |
| `春节` | 名称片段模糊匹配（唯一时直接用） |
| 不填 | **提示你补上**（回一句写法示例），不会去猜 |

> 为什么不给「不填 = 某一届」的默认值：站点内部有个「当前届」指针（`store.current_id`，
> 谁最近打开 / 新建过就是谁），但那是**实现细节**、前台早就不提这个概念了。拿它当默认值，
> 群友看到的会是「碰运气」的数据——同一句话今天问是这届、明天问变成那届。

**写错也不会卡住**：匹配到多届会列出候选；找不到会**列出可用编号**（并提示发
`比赛届次` 看全部），用户自己就能改对。

> 命令名刻意都带 `比赛` / `赛事` / `nte` 前缀：AstrBot 自己也有 `/help` 之类的内置命令，
> 用裸 `help`、`帮助` 很容易撞车。想改的话直接改 `main.py` 里 `@filter.command(...)`
> 的名字与 `alias` 集合即可。

## 其他实现细节（都是踩过坑之后定的）

* **插件加载时自检一次**：会调 `/api/bot/ping`，把「连上了哪台站点 / 当前哪一届 / 共几届」
  写进 AstrBot 日志。地址或令牌配错会立刻 warning——不用等群友发命令才发现。
* **命令参数一律宽松解析**：`比赛列表 第2页`、`比赛列表 2 页`、`比赛列表 2` 都认。
  参数**特意声明成字符串**而不是 `int`：AstrBot 在参数带 int 默认值时会对实参做
  `int()` 强转，转不动会**直接抛异常**（不是忽略这次匹配），整条命令失效。
* **复用一个 HTTP 连接池**：每次命令都新建 `httpx.AsyncClient` 等于重新握手；
  连接池在插件停用时关闭。
* **配置是「每次读」而不是构造时读死**：不同 AstrBot 版本注入插件配置的时机不一样，
  读死了会一直用默认值、所有命令都报「查询令牌不正确」。
* **列表翻页提示给的是真实命令**：会写「发『比赛列表 2』看下一页」，而不是让你发
  「下一页」——后者既不是命令也不是别名，照着发只会石沉大海。

## 关于 @

`比赛召集` 用的是消息链里的 **`At` 组件**，所以是**真正的 @**。

**它有两道闸门**（会 @ 一大片人的命令，不该谁都能触发）：

| 闸门 | 规则 |
| --- | --- |
| 认身份 | 只有**本届举办者**或**服务器管理员**能召集。插件调站点的 `/api/bot/managers` 拿到这批人的 **QQ**，再比对发命令的人——**在群里只能靠 QQ 认人**，而谁是举办者只有站点知道 |
| 冷却 | 同一会话默认 **60 秒最小间隔 + 每小时 6 次**；配置项 `call_cooldown` / `call_per_hour`，都设 0 = 关掉 |

两个容易踩的点：

* **组织者必须在站点「我的」页填自己的 QQ**，否则名单为空、谁也召集不了（命令会提示这一点）；
* 站点那套推送限流**管不到插件**（它只作用于网页「推送到群」的 HTTP 路径），
  所以冷却是在插件里单独做的——这也是为什么不能只依赖站点限流。

这一点值得说明：站点的**HTTP 推送**（`/api/qqbot/push`）只能把 `[CQ:at,qq=…]` 写进文本，
因为 AstrBot 的 OpenAPI 消息段只有 `plain / reply / image / record / file / video`，**没有 at 段**；
而插件跑在 AstrBot 内部，可以直接构造消息组件——想稳定 @ 到人就用这个命令。
平台不支持 `At` 时会自动退化成「@QQ号」纯文本，不会把命令打挂。

## 排错

| 现象 | 原因 |
| --- | --- |
| **机器人完全没反应** | 九成是**没 @ 机器人、也没带唤醒前缀**（见「怎么触发」）；其次看插件是否已加载 |
| `查询接口未启用` | 站点里还没生成令牌（或刚清除了） |
| `查询令牌不正确` | 站点重置过令牌，把新的填进插件配置 |
| `连不上比赛平台` | `base_url` 填错 / 站点没跑 / 网络不通 |
| `没有这一届：xxx` | 届次编号写错，用 `比赛列表` 看真实编号 |
| 启动日志里 `自检未通过` | 插件一加载就会探活，**先看这条**——它把上面几类问题提前暴露出来 |
